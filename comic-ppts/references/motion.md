# PowerPoint transitions and animation

Native motion is part of this template when supported by the final authoring environment. A static PNG/SVG/PDF cannot contain PowerPoint click behavior. Keep reveal text, hints, icons and character illustrations separate so native effects can target them. Use native PowerPoint animation, not a note that merely describes motion.

Defaults: short Fade transitions around 0.35 seconds, manual slide advance, no timed advance during activities, and restrained 0.25–0.5 second entrances. Use click-controlled answer/hint reveals. Reveal THINK, PAIR and SHARE teaching content one stage per click, keeping header labels visible if useful. Group text with its pane when the entire pane should enter together. Footer answers should be editable text on the footer graphic. Avoid auto-looping, flashing or decorative motion that distracts from listening.

The retained reference.pptx was opened, saved, reopened and played in Microsoft PowerPoint on this workstation. Its three slides have 1, 1 and 3 click steps respectively: full hero illustration entrance, an answer text reveal, and three activity prompt reveals. All had manual advance and a native slide transition. This evidence applies to that reference only. Validate newly generated decks again; do not claim every future export is tested.

Follow the available PowerPoint authoring workflow for authoring, rendering and finalization. Native motion may be lost in an exporter/importer. If the runtime does not expose native effects, an authorized installed PowerPoint COM pass can add them to the exported PPTX. scripts/apply-powerpoint-motion.ps1 is a reusable final pass with a JSON plan, supported effects Fade/Appear, and optional actual slideshow click checks. It acts only on its input copy, writes a new output, embeds no macro, and never closes unrelated decks. Read its parameters before use. Name target shapes deterministically when building the deck. Image names sometimes change on export; inspect and assign the actual name before applying effects.

Apply motion after the final round-trip export and retain it during validation. Confirm that the native timing elements and target IDs survive in the final PPTX. Open the exact final output in PowerPoint when available; check initial hidden state, each click step, target object, next-slide transition and manual pacing. Static renders verify layout only. If native playback is unavailable, disclose that it was not verified. If effects cannot be added, deliver the complete static deck plus a concise reveal plan and state the limitation. Do not claim a static plan is implemented animation.
